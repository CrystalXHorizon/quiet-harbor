# 留岸 · Quiet Harbor

中文 AI 情绪支持与互助社区。2.0 将账户、社区审核、AI 配置和对话 Harness 放到 Supabase 后端；普通成员无需填写 API Key。

**当前是待部署的新版本。** 没有 Supabase 配置时，只能使用明确标注的本地预设回复和练习。现有 GitHub Pages 站点不会因功能分支推送而被替换。完整上线步骤见 [DEPLOY.md](DEPLOY.md)。

## 这版包含什么

- 邮箱登录、申请加入、邀请码免审核、找回密码、验证器二次验证和退出登录。站长与管理员审批申请；站长管理邀请码、有效期和使用次数。绑定验证器后，密码登录仍需完成验证码挑战才能读取应用数据。
- 帖子草稿、提交审核、分类浏览、评论、收藏、屏蔽、举报及申诉。社区仅向登录成员开放。
- 修改已发布帖子时保留原来的已审核内容，新版本审核通过后才替换。管理员不能阅读未提交草稿，也不能审核自己的内容。
- 普通成员、社区管理员、站长三级权限。管理员处理审核与禁言，站长管理角色、封禁和 AI 配置；管理修改操作需要二次验证。
- 站长统一选择 AI 供应商、模型与接口，测试连接、设置调用额度、停用 AI，并查看用量和管理操作记录。
- 原有的聊天、感受选择、可选练习、结合最近聊天给建议，以及随时停止的入口。

没有私信、通知推送或云端聊天同步。用户帖子不自动采用项目的开源许可；发帖前会说明可见范围和审核流程。

## 本地开发

需要 Node.js 24：

```sh
npm ci
npm run check
npm test
npm start
```

打开 `http://127.0.0.1:4177/`。`npm start` 先构建再预览；修改源文件后重新运行 `npm run build`。前端发布目录是 `dist/`，不要直接发布 `public/`。

`public/site-config.json` 默认留空。配置自己的 Supabase Project URL 和公开 publishable/anon key 后才能使用真实账户与社区。AI Key、service_role key、数据库密码不能写进前端或仓库。浏览器测试使用拦截的模拟响应，不能替代真实项目验收。

## 数据与权限

浏览器只调用本站 Supabase API。函数先向 Supabase Auth 验证当前用户，再执行受权限约束的业务操作。数据库业务表开启 RLS，浏览器角色没有直接读写和执行内部 RPC 的权限；注册时不能自选管理员角色。站长由项目持有者按真实用户 UUID 初始化。

供应商 API Key 仅由站长在后台录入，经 AES-256-GCM 加密保存在数据库；加密主密钥单独放在服务端 Secrets 中。读取配置只返回是否已设置及末四位。修改目标地址或协议需要重新输入 Key，避免把已有凭据转送到新地址。自定义供应商需要部署者添加可信域名允许列表。

登录凭据由 Supabase SDK 保存在当前设备，用于恢复登录。聊天记录只保存在页面内存中，刷新、清空或切换账号时清除；应用不建立聊天内容表、不主动记录聊天正文。最近最多 12 条、总计 16000 字符的对话在发送时经过后端与所选供应商。供应商仍可能按其政策保留请求；停止或清空不能撤回已发送的数据。

社区帖子、评论、举报、申诉和管理操作记录保存在数据库中，属于持续保存的社区数据。旧版浏览器里保存的加密 API Key 不会被读取或上传，可在“账户与隐私”中删除。

## 服务端 Harness

`supabase/functions/_shared/harness.js` 执行输入校验、规则分流、单独的模型风险判断、固定陪伴提示、回答规则检查和单独的输出复核。通过检查后才显示完整回答，不显示未审查草稿。异常检查、截断和无效回复会暂停输出，不绕过检查。

禁止诊断、调整药物、催眠、恢复记忆、诱导身份切换、鼓励伤害和排他性依赖。支持倾诉、实际帮助、纠正误解、暂停和减少提问等本轮意图。前端保留快速现实支持提示，真正的调用限制和 AI 检查由后端执行。

正常一轮通常最多请求模型三次；使用同一个模型不等于独立临床判断。额度按发起的轮次原子计数，失败或取消也消耗本轮额度，每日按 UTC 重置。这是次数限制，不是精确的服务商账单金额上限。

检查可能误判或漏判，未经过临床验证。留岸不是治疗师、医疗器械或急救服务，不诊断、不承诺治愈；没有真人实时监测或自动报警。真实语言质量的验收案例见 [evals/conversation.md](evals/conversation.md)。

## AI 供应商

保留 18 个供应商预设，包括 DeepSeek、OpenAI、Anthropic、Gemini、百炼、Kimi、智谱、火山方舟、MiniMax、混元、百度千帆、阶跃星辰、xAI、Mistral、Groq、硅基流动、Together AI 和 OpenRouter。自定义支持 HTTPS OpenAI Chat Completions 或 Anthropic Messages 协议。仅提供 Responses、OAuth、云签名或本地 HTTP 的接口不在本版范围内。

预设代表协议适配，不代表已使用每家的付费密钥实测。站长应按账户权限填写可用模型，并用不含私人聊天的连接测试确认。连接测试也可能计费。

## 项目结构与验证

| 目录 | 内容 |
|---|---|
| `public/` | 聊天、账户、社区和管理页面源文件 |
| `supabase/migrations/` | 数据库结构、权限、审核状态与配额逻辑 |
| `supabase/functions/` | 身份校验、业务 API、密钥加密和 AI Harness |
| `supabase/tests/` | 数据库权限与业务流程断言 |
| `scripts/` | 构建、静态预览、语法检查与浏览器联调脚本 |
| `test/` | API、数据库、认证、协议和 Harness 自动化测试 |

自动化测试使用模拟供应商与本地 PostgreSQL 引擎，不产生实际 AI 费用。覆盖跨用户权限、草稿与修改版本隔离、审核、封禁、MFA、额度、密钥保护、身份变化和故障回退。真实邮箱收信、邀请/密码恢复、云端 Edge 部署及付费模型仍需按 [部署验收清单](DEPLOY.md#8-上线验收) 在自己的项目中验证。

`server.mjs`、`public/vault.js` 和部分直连测试保留为旧版本兼容代码，新版构建不使用旧服务器，也不发布浏览器密钥库或直连 Harness。Dockerfile 仅预览构建后的前端，不能替代 Supabase 后端。

GitHub Actions 检查功能分支并生成前端构建包；只有 main 分支且公开 Supabase 配置齐全时才部署 Pages。WebMCP 只提供打开练习的工具，不暴露读取或发送聊天的能力。
