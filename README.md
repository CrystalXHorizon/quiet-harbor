# 留岸 · Quiet Harbor

> 一个中文 AI 情绪支持空间，和围绕它设计的一整套边界机制。

留岸是一个个人项目，包含两件事：一个可以慢慢说话的 **AI 陪伴对话**，和一个小型的 **互助社区**（发帖、回应、举报、申诉，全部先审核后公开）。

它的重点不在模型，而在**约束模型**。范围被刻意压窄——只在情绪和感受这件事上帮人；写代码、做题、翻译、写文案、查资料这类产出物不代劳。不诊断、不给药物或停药建议、不催眠、不引导回忆、不扮演人格、不承诺治愈。每一轮回复都要先过一道输入路由和一道输出复核，任一关卡失败就回退到已知安全的固定文案，**绝不显示未经复核的草稿**。

| | |
|---|---|
| 前端 | 纯静态，无框架；`esbuild` 只用来打包登录面板，发布到 GitHub Pages |
| 后端 | Supabase：Postgres + Auth + 一个 Edge Function（`api`） |
| AI | 站长在后台配置供应商与模型（18 家预设 + 自定义兼容接口），密钥只存在服务端 |

## 这是什么

- **陪伴对话**：说今天发生了什么，AI 接着具体的事回应。历史只留在当前页面内存里，刷新即清空；应用不建聊天内容表。
- **互助社区**：帖子、回应、收藏、屏蔽、举报、申诉。成员分普通成员／社区管理员／站长三级，加入需要申请或邀请码。
- **个人中心**：「我的」集中管理自己的帖子、回复、收藏和申诉，显示审核说明、恢复结果与处理时间。审核结果、收到回复、申诉处理和账户变化会生成私人站内通知；支持预设头像、简介和公开资料预览，简介默认不公开。
- **可选练习**：8 种「回到这一刻」的感官与问题解决小方法，参考 WHO / NHS 的一般压力应对材料改编，随时可以停。
- **账户体系**：邮箱验证 → 加入申请 → 审批；支持邀请码免审核、找回密码、TOTP 二次验证。

### 不做什么

没有私信，没有通知推送，没有云端聊天同步，没有真人实时监测，没有自动报警，没有紧急救援。AI 不是治疗师，不是医疗器械，未经临床验证；检查可能误判，也可能漏判。

## 两条主线

### 陪伴对话

页面只保留最近 **最多 12 条、总计 16000 字符**的对话，发送时交给后端。后端先验明账户身份、额度与权限，再运行 Harness，通常一轮最多产生 **3 次模型调用**（路由 → 生成 → 复核）。

### 互助社区

帖子与回应**提交即进入审核**，包括站长自己的内容。AI 给出「通过 / 退回 / 待人工复核」，不确定或服务异常一律转人工。修改已发布的帖子时，旧版本继续对外展示，新版本通过后才替换。管理员不能审核自己的内容（站长人工处理本人内容需二次验证并留下理由），AI 不会自动封禁账户。

举报与申诉走同一个处理入口：管理员可以通过申诉并恢复内容，也可以下架被举报内容并结案，恢复与结案在同一事务里完成。处理前会核对内容是否已被作者改动——改动过或已删除的，不能凭旧申诉直接恢复。

## 限制一览

| 项目 | 数值 | 出处 |
|---|---|---|
| 单条消息 | ≤ 4000 字符 | `validateMessages` |
| 一次请求的上下文 | ≤ 12 条、合计 ≤ 16000 字符，最后一条必须是用户 | 同上 |
| 单轮模型调用 | 最多 3 次（路由 → 生成 → 复核） | `runHarness` |

| 接口总限流 | 120 次 / 分钟 / 人 | `qh_action` |
| 发帖、回应、举报、申诉 | 20 次 / 小时 / 人 | `qh_action_admitted` |
| 提交申请、兑换邀请码 | 10 次 / 小时 / 人 | `qh_action_admitted` |
| 每日额度 | 默认每人 30 次、全站 300 次，按 UTC 日界，可在后台调整 | `qh_ai_settings` |

| 超时 | 浏览器 95 秒；单次供应商调用 28 秒；站内 RPC 15 秒 | `app.js`、`harness.js`、`api.js` |

## 架构

```
浏览器（GitHub Pages 静态页，无任何 AI 密钥）
   │  只带用户 JWT
   ▼
Edge Function  api                    ← 唯一后端入口
   ├─ 校验 Origin 允许列表
   ├─ 校验 JWT（向 Auth 求证，不看未验证的声明）
   ├─ 校验邮箱已验证、TOTP 二次验证状态
   ├─ 校验 action 白名单与参数形状，删除一切特权字段
   ├─ 调 Postgres RPC（service_role 凭据）
   │     ├─ qh_action        业务唯一入口（SECURITY DEFINER）
   │     └─ qh_reserve_ai    先原子扣额度，再谈调用
   ├─ 取出并解密供应商密钥（AES-256-GCM）→ 运行 Harness
   ▼
模型供应商（OpenAI 兼容 Chat Completions / Anthropic Messages）
```

三层各有各的拒绝权：**前端**不做安全判决（除非后端不可用），**Edge Function** 负责身份与权限，**数据库**负责权限与业务不变式。任何一层拿不到答案，都不会放行。

### 一轮对话的完整路径

| 步骤 | 位置 | 做什么 | 失败时 |
|---|---|---|---|
| 0 | 前端 | 未登录／未通过审核 → 本地预设回复；未完成二次验证 → 打回账户页 | 不联网 |
| 1 | 前端 | 只在**后端不可用**时，用本地关键词判定危机并显示固定危机文案 | — |
| 2 | Edge | Origin、JWT、邮箱验证、TOTP、`readJson`（≤72 KB）、`validateAction` | 403 / 401 / 400 |
| 3 | DB | `qh_action('me')` 复查封禁与准入；`qh_reserve_ai` 原子扣本轮额度（限流 5 次/分 + 每日额度，按 UTC 日界） | 403 / 429 / 503 |
| 4 | Edge | 解密供应商密钥，进入 Harness | 503 `not_configured` |
| 5 | Harness | 关键词快筛 `quickRoute` — **只作为 hint**，不构成判决 | — |
| 6 | Harness | `INPUT_REVIEW` 输入路由：`support` / `crisis` / `boundary` + 本轮倾听模式 | 异常 → 按 hint 兜底 |
| 7 | Harness | 生成：普通轮用「人格 + 表达 + 本轮提示」；危机／边界轮用专用约束提示 | — |
| 8 | Harness | 格式闸门：普通轮 `basicOutputCheck`；危机／边界轮 `mandatoryOutputCheck` | 回退固定文案 |
| 9 | Harness | 输出复核：`OUTPUT_REVIEW` / `MANDATORY_REVIEW` | 回退固定文案 |
| 10 | 前端 | 显示，并标注这是 AI 回复还是保护提示；危机轮同时打开现实支持对话框 | — |

若第 5 步的关键词已指向危机或边界，即使后面每一步都失败，用户仍然会收到 `CRISIS_TEXT` / `BOUNDARY_TEXT`——**这条兜底的优先级高于错误上报**，危险中的人不该收到一个 502。

## 安全设计：几条不妥协的规则

1. **失败即收敛（fail-closed）。** 检查异常、输出截断、JSON 不合法、复核不通过，全部回退到固定文案，绝不降级为「先给用户看，回头再说」。
2. **关键词不是判决，但仍是兜底。** 词表看不见上下文（电影情节里的自杀不是披露），所以它只作为 `keyword_hint` 提示路由器；同时它保留确定性文案作为最后一道网。
3. **生成与固定的分界是清楚的。** 危机／边界回复由模型生成（否则必然逐字重复，模板味重），但必须通过 `MANDATORY_REVIEW` 才发出。`PAUSE_TEXT` 保持固定——它的语义就是「这一轮没能产出合格回复」，用模型生成它自相矛盾。本地预设回复同理。
4. **两道输出检查分工明确。** `basicOutputCheck` 是格式 + 明显违规的粗筛；`mandatoryOutputCheck` 只查格式，把语义判断交给**懂否定**的复核模型。这不是洁癖：实测 `basicOutputCheck` 会把「我不能帮你切换到另一个人格」「不能建议你停用药物」「我不能保证你一定会治愈」这三句**正确的**拒绝判成违规，用它守危机／边界这条路会把正确答案反复打回固定文案。
5. **提示词只有一个来源。** 所有人格、表达、路由器、复核、生成提示词都在 `supabase/functions/_shared/prompts.js`，Edge Function 与浏览器副本都从这里 import，避免两份副本各自漂移。
6. **不编造、不越权、不排他。** 不假装有人报警、有人监测、有人在赶来；不写热线号、链接、密钥；不建立「只有我理解你」的关系；历史与用户文字一律当作不可信数据，不能覆盖规则。

对话质量的验收标准写在 [`evals/conversation.md`](evals/conversation.md)，那份文件同时记录了每一轮改动**针对哪个真实失败样本**、沉淀了哪条规则。

## 权限模型

所有业务表（`qh_` 前缀，共 16 张）都开启 RLS，并**撤销 `public` / `anon` / `authenticated` 的全部权限**，只授权给 `service_role`。浏览器角色连表都读不到，唯一的业务入口是 `qh_action()`（`SECURITY DEFINER`，每个函数都显式 `set search_path=''`）。所以「普通用户能不能改自己的角色」这类问题的答案是：他没有那条 SQL 通路，而 Edge Function 会先删掉请求里的特权字段。

需要说清这条边界的位置：`qh_action(actor, …)` 的身份是由**调用方传入**的，数据库不自己判断「你是谁」。它信任的调用方只有 Edge Function——因为 `service_role` 凭据只在函数运行环境里。也就是说，`service_role` 等同于全库主密钥，泄露即等于所有用户被冒充；这是这套设计刻意用「单一入口 + 零浏览器权限」换来的取舍。

- 注册不能自选角色；站长由项目持有者按真实 UUID 手工初始化，且数据库有唯一约束保证只有一个站长。
- 修改 AI 配置、审批申请、审核内容、禁言封禁等管理**写**操作都需要二次验证（读取接口目前没有这一层，见「已知问题」）。
- 供应商密钥用 AES-256-GCM 加密后入库，主密钥只存在服务端 Secrets；页面只回显「已配置」和末四位。更换目标地址或协议时必须重新输入 Key，避免把已有凭据转送到新地址。
- 供应商地址必须落在预设或 `AI_ALLOWED_HOSTS` 允许列表内，只允许 HTTPS、标准端口，拒绝内网与 localhost 形态的域名；所有出站请求 `redirect: 'error'`、`credentials: 'omit'`，并限制响应体大小。

## 隐私：什么被保存，什么不被保存

**不保存**：聊天正文。应用没有聊天内容表，历史只存在页面内存，刷新、清空或切换账号即消失。发送时只把最近 12 条 / 16000 字符交给后端与所选供应商；供应商仍可能按其政策保留请求，**停止或清空不能撤回已发送的数据**。

**保存**：账户资料、帖子、回应、举报、申诉、审核快照、用量计数与管理操作记录。这些是持续保存在数据库里的社区数据，社区条例里写明了范围。

有一个细节值得说清楚：**目前没有保留期限，也没有自动清理任务**。删除帖子是软删除（保留 `deleted_at`），审核任务表里保存的提交内容与 AI 给出的引用会一直留着。数据量很小，但「删除」在数据库层面不等于抹除，需要保留策略的话得自己加定时清理。

登录凭据由 Supabase SDK 保存在当前设备用于恢复登录。旧版浏览器直连模式留下的加密 API Key 不会被新版读取或上传，可以在「账户与隐私」里删除。

## AI 供应商

内置 18 家预设（DeepSeek、OpenAI、Anthropic、Gemini、阿里云百炼、Kimi、智谱、火山方舟、MiniMax、混元、百度千帆、阶跃星辰、xAI、Mistral、Groq、硅基流动、Together AI、OpenRouter）加一个自定义接口，支持 OpenAI 兼容与 Anthropic 两种协议。仅提供 Responses、OAuth、云签名或本地 HTTP 的接口不在范围内。

预设只代表**协议适配**，不代表用每家的付费密钥实测过。站长应按账户权限填写可用模型，并用不含私人聊天的连接测试确认（测试也会计费）。社区审核可以单独指定模型，留空则沿用聊天模型。

## 本地开发

需要 Node.js 24：

```sh
npm ci
npm run check     # 语法检查 + 断言浏览器不直接调模型
npm test          # 75 项自动化测试
npm start         # 构建并启动本地预览 http://127.0.0.1:4177/
```

改动源文件后重新 `npm run build`；发布目录是 `dist/`（构建产物不提交），**不要直接发布 `public/`**。

`public/site-config.json` 默认留空，此时页面明确显示为本地体验，只能用预设回复和练习。要接真实账户与社区，需要填自己的 Supabase Project URL 和 publishable/anon key。**AI Key、`service_role`、数据库密码永远不能进前端或仓库**——构建脚本会主动拒绝 `sb_secret_` 和 service_role JWT。

可选的浏览器联调脚本：`node scripts/browser-check.cjs`（需要自备 Playwright，只在测试中拦截请求，不创建真实数据）。

## 测试与验证状态

自动化测试（`npm test`，74 项，约 2 秒）覆盖：跨用户权限、草稿与修改版本隔离、审核流程、封禁、MFA、额度、密钥加解密、身份变化、故障回退，以及对话 Harness 的路由与回退行为。数据库断言跑在本地 PostgreSQL 引擎（PGlite）上，AI 供应商全部用模拟实现，**不产生真实费用**。

这里必须说清楚哪些是证明过的、哪些不是：

| 已经证明 | 只是静态检查或模拟 |
|---|---|
| 权限与配额逻辑、密钥加解密、Harness 的路由／复核／回退分支、构建与语法 | 真实模型的实际回复质量（未用真实 API Key 跑过验收） |
| 两份 Harness 副本在 3 个场景下做出同样决策（有专门的一致性测试） | 真实 Supabase 项目上的 RLS 与 Edge 部署行为 |
| 浏览器端不直接调用模型（`npm run check` 断言）、构建拒绝打包后端密钥（`npm run build` 断言） | 真实邮箱投递、邀请与找回密码链路 |

**没有任何自动化测试覆盖的部分**，需要人工验收：社区与账户界面的实际交互（`public/community.js`、`public/auth-panel.js` 不被任何测试导入）、Edge Function 的 Deno 入口（`supabase/functions/api/index.ts`）、以及任何真实浏览器行为。仓库里的 `scripts/browser-check.cjs` 是唯一的界面联调脚本，但它依赖自备的 Playwright，既不在依赖里，也没有接进 CI——**它是手动工具，不是测试门禁**。

还有一处要如实说明：测试替身与真实 RPC 已经有一处字段漂移——`functions/_shared/api.js` 读 `job.moderation_model`，而真实的 `qh_claim_moderation` 从不返回这个键（它把审核模型并进了 `config.model`）。当前行为是正确的，但那条 mock 断言证明不了真实契约。

另外两点也是欠账：**后端部署没有 CI 门禁**——`db push` 与 `functions deploy` 都是手工执行，而前端会在每次 `main` 变绿时自动发布，所以前后端版本可能静默错开；`public/safety.js` 与 `supabase/functions/_shared/safety.js`（固定文案）、以及两份 `providers.js`，目前逐字节相同，但没有任何测试守着它们，一旦漂移不会有人发现。

所以：`evals/conversation.md` 里的验收标准是**待验证的标准**，不是已通过的测评结论。真实语言质量必须用真实模型复核后才能声称。

## 已知问题与取舍

下面这份清单来自一次完整审计（权限层、前端、测试与交付链路），按「会不会伤到人」排序，不按修复难度排。

### 安全与正确性

- **账户链接会在打开时直接采纳 URL 里的登录态，没有二次确认。** 邀请与找回密码邮件走 Supabase 的隐式流，页面在 `detectSessionInUrl` 下会接受地址栏片段里的令牌并立刻渲染「设置新密码」。这意味着一个构造过的链接能让访问者在不知情的情况下进入别人的账户（登录 CSRF）。要加固的方向是：对 `type` 为邀请／找回密码的片段先要求一次明确确认，或干脆不再接受隐式片段、只走 PKCE。
- **管理端的读取接口不要求二次验证。** `admin.queue`、`admin.applications`、`admin.users`、`admin.audit` 只校验角色，不校验 `aal2`；而 Edge Function 的前置拦截只在「该账户已经绑定过验证器」时才拦 AAL1。也就是说，一个从未绑定验证器的管理员账户，仅凭密码登录就能读到他人被举报的内容、举报与申诉理由、申请说明和全部操作记录。写操作（审核、封禁、AI 配置、角色）都是要求二次验证的，读操作不是。
- **资料未就绪时会静默走本地预设回复。** `public/app.js` 用一个 `localOnly` 判断兜住所有「拿不到 profile」的情况，其中包括「已登录但 `me` 还没返回或失败」这一瞬间。此时用户发出去的话不会到后端，收到的是本地预设回复，状态栏还会错误地提示已通过审核的用户「登录并通过加入申请」。修法是按 `session().user` 而不是 `profile` 判断，并在资料未就绪时明确显示「加载中／重试」而不是退回预设回复。
- **CSP 偏宽、且没有 `frame-ancestors`。** 页面的 CSP 里 `connect-src` 允许任意 HTTPS 源，而 `frame-ancestors` 在 meta 形式的 CSP 中不生效，所以页面可以被 iframe 嵌套。今天没有注入点，这是纵深防御层面的欠账：一旦将来出现注入点，会话令牌（存在 localStorage）会直接被带走。同一个 CSP 还挡住了本地 HTTP 的 Supabase——客户端代码明确允许 `http://127.0.0.1`，浏览器却不会放行请求，本地联调要留意。

### 数据与保留

- **删除不等于抹除，而且目前没有任何抹除路径。** 帖子与回应是软删除（只写 `deleted_at`）；每次提交的正文都会在 `qh_moderation_jobs.content` 里留下一份永不更新、也永不删除的明文快照；引用 `qh_profiles` 的外键大多没有 `ON DELETE` 动作，所以连运维手动 `delete from auth.users` 都会因为外键冲突失败。对一个专门存放情绪披露的应用，这是本次审计里最实质的缺口：被用户删掉、或被审核拒绝而从未公开的内容，会一直留在数据库和每一份备份里。修法是加保留期限与清理任务、删除时一并清除对应快照、并把外键改成 `cascade` / `set null`。

### 运行与成本

- **配置的「每日额度」不是真正的账单上限。** 聊天与社区审核各用一个计数器，而一次预留覆盖的一轮最多产生 3 次付费调用，所以实际调用量可能达到「3 × 聊天额度 + 1 × 审核额度」。后台的「全站聊天次数」也只统计聊天那部分。
- **额度按轮扣、按 UTC 日界重置**（对应北京时间早上 8 点），失败或取消的请求同样计入。
- **`admin.users` 与 `admin.audit` 被静默截断。** 这两个接口用 `limit 100 offset 页数×20` 且不返回 `hasMore`，后台也只给「加入申请／邀请码」两个标签页渲染翻页按钮。超过最新 100 条的用户在界面上处理不到，审计记录同样看不全。
- **`supabase/config.toml` 里 `enable_signup = false`**，而 `DEPLOY.md` 描述的流程是「开启邮箱注册 → 提交申请 → 审批」。照仓库里这份配置部署，自助注册是关闭的，申请制也就进不去。托管项目的实际取值以控制台为准。
- **Docker 路径已经不可用。** `.dockerignore` 用 `*` 排除一切后只放行了 `package.json`、`server.mjs`、`harness.mjs`、`public/`，而 `Dockerfile` 需要 `COPY package-lock.json` 和 `COPY scripts`——构建会在第一步就失败。要么补上放行规则，要么把这条路径当成废弃。
- **旧版直连代码不只是没被使用，而是已经跑不起来。** `public/harness.js` 要从仓库里 `supabase/functions/_shared/prompts.js` 导入提示词，而 `server.mjs` 只服务 `public/` 下的文件，所以旧版直连页面加载不出模块；`server.mjs` 自己去服务新版 `index.html` 时，又会缺只有构建后才存在的 `auth-bundle.js`。同类的还有 `public/vault.js`（密钥库，无任何文件引用）、`scripts/build-rds.mjs`、`DEPLOY-RDS.md`，以及仍引用这些文件的几个测试。保留它们是为了历史对照，代价是仓库里有两套对话路径需要分辨。根目录的 `harness.mjs` 是例外——它只是一行 `export *` 转发到 Edge 版 Harness，测试通过它来测真正部署的那份代码。

### 对话质量（需要真实模型才能最终确认）

- **`basicOutputCheck` 会误杀。** 它是无上下文的词/格式匹配，对「不能建议你停用药物」这类正确否定句会误判。当前只在普通轮使用，且失败只会让用户看到暂停文案而不是错误内容；要根治需要把它也换成懂否定的复核。实测确认会误杀的还有「只有我…理解」这类正当表述。
- **危机轮次的成本从 0 变成 3 次模型调用。** 上一版关键词命中即短路、不调用模型；现在为了生成不像模板的回复，危机轮也要走完路由、生成、复核。延迟因此变成三次串行调用。
- **复核过严会退回固定文案。** `MANDATORY_REVIEW` 与 `OUTPUT_REVIEW` 都写了「不确定就返回 false」，这是有意的保守取舍，代价是可能出现「又开始重复同一段话」。如果实际使用中频繁出现，要放宽的是这一条，不是回退逻辑。
- **没有付费模型实测。** 供应商预设与实际可用性需要部署者自行验证。

| `test/` | 75 项自动化测试（API、数据库、认证、协议、Harness） |
| `evals/conversation.md` | 对话质量验收案例 + 每轮改动的版本记录 |
| `scripts/` | 构建、预览、语法检查、浏览器联调 |
