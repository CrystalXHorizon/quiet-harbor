# 留岸手机端 UI 设计与实施规格

设计：Codex；实施：DSH。日期：2026-10-17（Asia/Shanghai）。

## 目标与现状

延续现有浅灰青和炭灰两套颜色，安静、易读、单手可用。手机先能开始聊天，再按需使用支持工具。

已在本地真实页面检查 390×844：顶部侧栏 146px，加第二层工具栏约 96px；输入框 top=790.89、bottom=937.89，发送按钮不在首屏。整页约 1740px，感受与练习卡排在聊天后面。证据：`test-results/mobile-ui-2026-10-17/before-chat.png`。

## 界面骨架（≤620px）

```text
┌────────────────────────────────┐
│ 留岸           外观  现实支持  ⋯ │ 60px 顶栏
├────────────────────────────────┤
│ 慢慢说，我在听。       本地体验 │ 简短页头
│                                │
│ 留岸                           │
│ 今天想聊点什么？……             │ 聊天区域填满剩余空间
│                                │
│ [选一个感受] [今天有点难熬] →   │ 单行可横滑建议
│ 本地体验……                     │ 真实状态提示
│ ┌────────────────────────────┐ │
│ │ 写下你想说的话……     [发送] │ │ 底部输入区
│ └────────────────────────────┘ │
│ 聊天仅在本页 · 刷新清空   清空 │
│ AI 不能替代专业支持或紧急救援。 │
├────────────────────────────────┤
│  ◌ 聊聊   ☷ 社区   ◎ 练习  ○ 我的│ 固定底部导航
└────────────────────────────────┘
```

- 顶栏高度约 60px；品牌小字英文在手机隐藏。现实支持始终可见，点击打开原 help-dialog；外观 44px 方形触控目标；更多按钮 44px，打开原生 dialog/bottom sheet。
- 底部仅四入口：聊聊、社区、练习、我的。每项至少 44px 可点，高度约 64px 加 safe-area-inset-bottom；图标20px、标签12px。选中项只用柔和底色/细边界，无高反差大色块。练习打开既有 ground-dialog，不新增页面或后端行为。
- 更多面板放账户、通知、管理后台（沿用权限显示）、账户与隐私、陪伴边界。现有按钮 ID 保持唯一，复用实际按钮与 handler，不能只复制一套会失去鉴权/未读数同步的装饰按钮。切换视图或打开其他对话框时关闭更多面板，Escape 与关闭按钮有效，焦点返回触发器。
- 桌面 >620px 保持原侧栏/顶部结构；resize 时实际节点须回到正确位置，不能丢失 ID、焦点、hidden 或事件。

## 聊天

- 手机采用动态视口高度的纵向布局：顶栏、内容、输入区、底部导航。默认390×844及375×667中发送按钮首屏完整可见；小高度/横屏允许合理滚动，不能用 overflow:hidden 掩盖内容。
- 页头约56px，h1 22–24px，保留宋体标题；移除手机重复的“与我聊聊/当前对话”标签与“今天的你…”副标题，桌面保留。mode-badge 11–12px。
- 会话为可滚动区域，正文16px、行高1.8；气泡内边距14px，最大宽度约88%，头像28px。长词/链接换行。避免固定260px高度留下空洞。
- 建议单行44px触控，允许区域内横向滑动，整个文档无横溢；不要把四个建议挤成难辨的细小胶囊。
- 输入字号≥16px；约48px最小输入高度，总输入区约88–100px，发送44px触控。手机不显示桌面 Enter 提示；触屏普通 Enter 为换行、按钮发送，桌面键盘继续 Enter 发送/Shift+Enter换行，并保留中文输入法 isComposing 检查。
- 页面没有输入焦点时可使用 100dvh；键盘弹出用 visualViewport 的高度/offset 与明确的清理逻辑保证发送可达，不能让底栏盖住输入；必要时键盘打开隐藏底栏，关闭后恢复。resize/旋转不残留 body 样式。不要用 UA 字符串识别设备。
- 状态、错误、停止生成、隐私说明继续可读可达，不能为了压高度隐藏必要提示。底部免责声明可短写，保留完整边界和许可入口于更多面板。清空仍遵守原确认行为。
- 手机上的完整右侧支持卡不再堆到聊天下面；“选一个感受”打开原生底部面板，包含原 checkin 的实际节点、全部六种感受、三个后续动作、状态；使用后可回聊天。桌面继续原右栏。练习入口直接复用既有弹窗。不得删除支持功能或改变策略/安全文案。

## 社区、帖子、个人中心、弹窗

- 手机内容左右16px，垂直间距16/24px，卡片圆角14px、内边距16px；标题22–24px，帖子标题18–20px，正文16px、次要信息12–13px。不新增字体、图片或依赖。
- 社区标题与主操作排成紧凑的首行，宽度不够再换行；规则保持可折叠，筛选在一层内自然排布，卡片操作≥44px，不遮挡分页/底部内容。
- 帖子阅读继续原近全屏阅读弹窗和固定关闭入口，正文不挤，回复/举报/收藏/滚动仍有效。
- 个人中心六栏目用清楚的3列×2行紧凑网格（短标签：帖子、回复、收藏、申诉、通知、设置；完整 accessible name 可保留），不横挤六个长按钮。统计4等列，小屏可2列，保留原数据。资料动作和长昵称自然换行。
- 所有手机表单 input/select/textarea ≥16px，触控目标44px；原生 dialog 最大高度遵从动态视口，内容滚动，关闭按钮固定/粘在可见区域，横屏可达底部操作；安全区留白。
- 浅色/深色都复用 theme.css token，保留单层输入焦点。不得给全站加 overflow-x:hidden 来掩盖布局错误。

## 实施边界

只改前端展示与导航 glue。可以修改 public/index.html、style.css、community.css、personal.css、theme.css、app.js 及必要的 personal.js/community.js 展示代码。优先用现有文件；若引入模块需正确更新 build/preview 白名单。

保留现有提示词/eval/safety/README 等未提交内容，禁止改后端、数据库、认证权限、真实用户数据、真实邮件或模型调用。不得 commit/push/deploy。不得读取 .env、.credentials.yaml 或任何秘密。DSH 使用自己已配置运行环境即可。

## 验收与交付

1. npm run check / npm run build / 既有 browser regression（fixture only）。不降低既有断言来让测试通过；如果布局改变需适配导航路径，要保持原功能验证。
2. 320×568、375×667、390×844、430×932、横屏844×390、桌面1280×900。浅色/深色、首屏发送可见、无文档横溢、底栏不遮挡、触控/字体检查。
3. 点击四导航、更多所有入口、权限下的管理员入口、通知、感受面板→聊天、练习、外观、登录/退出、社区帖子/回复、个人六栏；resize 跨620再返回，不丢按钮和事件。
4. 测键盘 resize 与聚焦滚动，长消息/长状态仍能发送/停止；真实 iOS/Android 软键盘若只有模拟检查需如实标注。
5. 在 test-results/mobile-ui-2026-10-17/ 保存 after-chat-light.png、after-chat-dark.png、after-community.png、after-personal.png、after-mood.png、after-more.png、desktop.png、检查结果和 IMPLEMENTATION.md。交付具体改动、验证结果、剩余限制，Codex 根据截图和差异验收。
